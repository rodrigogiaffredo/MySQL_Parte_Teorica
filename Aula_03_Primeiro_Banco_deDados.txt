
# CRIAÇÃO DE BANCO DE DADOS SQL

# O objetivo de um banco de dados é registrar instâncias separadas de objetos com características
# semelhantes.

# Por exemplo, uma ficha de dados pessoais que contenha nome, idade, peso, altura e nacionalidade,
# pode ser utilizada para registrar o mesmo tipo de informação acerca dessas características para
# muitas pessoas, ainda que os valores sejam totalmente diferentes.

# Todas as fichas cadastrais das pessoas registrarão as mesmas características, porém para cada uma
# das pessoas teremos seus valores particulares.

# Algumas características até podem ser de preenchimento opcional, mas todas as pessoas que usarem
# essa ficha terão à disposição o mesmo conjunto de características para registro de valores.

# Podemos dizer então que a ficha de cadastro é uma tabela de dados com características próprias.

# Do mesmo modo, eu poderia ter uma tabela para cadastrar jogos, contendo características tais como
# título, fabricante, gênero e a plataforma.

# Uma das grandes virtudes da organização das informações em tabelas de dados é a possibilidade de
# separar objetos de acordo com as semelhanças e diferenças de suas características.

# O conjunto das minhas tabelas é o que gera meu banco de dados. Podemos dizer portanto que o banco
# de dados organiza os objetos com características semelhantes em diferentes tabelas, as quais estão
# estruturadas de acordo com as semelhanças entre esses objetos (no meu exemplo, a tabela 'dados 
# pessoais' para as pessoas, e a tabela 'catalogo' para os jogos, formam o meu banco de dados).

# O conjunto de características de cada pessoa constitui o registro daquela pessoa, assim como o
# conjunto de características de cada jogo constitui o registro daquele jogo.

# Bancos de dados contém tabelas.

# Tabelas contém registros.

# Registros são compostos por campos.

# Ou seja, quando criamos um banco de dados, logo em seguida criamos suas tabelas, e dentro delas 
# criamos seus campos.

# Assim como nos algoritmos as variáveis eram associadas aos seus diferentes tipos primitivos, os
# campos de uma tabela também precisam dessa definição.

# Existem muitos tipos primitivos no SQL, e os quatro principais clusters de agrupamento são:

# - NUMÉRICO
#   Subdivisões: INTEIRO, REAL, LÓGICO
#   Precisão: no caso do INTEIRO: TinyInt, SamllInt, Int, MediumInt, BigInt
#             no caso do REAL: Decimal, Float, Double, Real
#             no caso do LÓGICO: Bit, Boolean

# - DATA / TEMPO
#   Subdivisões: não há.
#   Precisão: Date, DateTime, TimeStamp, Time, Year

# - LITERAL
#   Subdivisões: CARACTERE, TEXTO, BINÁRIO, COLEÇÃO
#   Precisão: no caso de CARACTERE: Char, VarChar
#             no caso de TEXTO: TinyText, Text, MediumText, LongText
#             no caso de BINÁRIO: TinyBlob, Blob, MediumBlob, LongBlob
#             no caso de COLEÇÃO: Enum, Set

# - ESPACIAL
#   Subdivisões: não há.
#   Precisão: Geometry, Point, Polygon, MultiPolygon


# Importante: o dimensionamento das tabelas é fator fundamental da performance do sistema, por isso
# é crucial que esse trabalho seja executado com extrema precisão. Precisão é dada pela quantidade
# de bytes que serão utilizados para armazenar o dado.

# Por exemplo, o TinyInt do subtipo INTEIRO ocupa muito menos bytes que o BigInt.

# Outra boa ilustração é a diferença entre Var e VarChar: se eu digo que um campo CARACTERE Char 
# terá 30 letras, e o nome da pessoa for apenas João, serão ocupados 4 espaços com letras, e os 
# demais com espaços. Por outro lado, se eu disser que se trata de um CARACTERE VarChar com até 30
# letras, o nome João ocupa 4 espaços, e os demais ficam vazios.
